# Plan: crew-net v0.1.0

Goal: a tagged v0.1.0 that the reflex developers can install and run for the
two-week live run. The plugin installs from this repo's marketplace and brings
the CLI. The docs are complete. The end-to-end scenarios pass on the sandbox
repo.

This plan sets direction, order and acceptance, not line-level tasks. Each
workstream owns the modules named in [architecture.md](../architecture.md) and
follows its dependency rules. Inside a module, the implementer chooses the
details. A change that crosses a module boundary or changes a contract goes
back to the manager first.

## Ground rules for every workstream

- Read [design.md](../design.md) and [architecture.md](../architecture.md)
  before starting. They win over this plan.
- One workstream = one branch = one worktree = one PR. Small PRs are fine.
- TypeScript strict. Node 22 runtime. No runtime dependencies. Dev tooling is
  fixed by W0; do not add tools without asking.
- Tests are part of the work, not a follow-up: the test specifications in
  architecture.md are the minimum.
- Done = `make check` passes (typecheck, lint, tests, fitness checks), the PR
  description says what changed and how it was verified, and any contract
  change is reflected in `protocol` fixtures and the docs.
- No live writes to any repo except `alexei-led/crew-net-sandbox`. Never touch
  `doiteng/reflex` or omni.

## End-to-end scenarios (W8)

Single GitHub account for now, so scenarios that need two logins are marked
and run when a second account exists.

1. Digest at session start and after `/clear` shows the other laptop's draft PR.
2. Radar: both laptops change one file and push; the other lead gets a conflict
   finding within one fetch cycle. A contract path change raises a wake.
3. Message round trip: held in the band while the receiver types; delivered as
   context on the next prompt; with the receiver idle, auto-wake replies once.
4. Routing: a developer with two sessions; a `crew → dev` message reaches one.
5. Merge gate: `depends-on` blocks `gh pr merge` and `--auto`; allows after
   the dependency merges.
6. Prompt injection: a peer comment asking to merge or edit files causes only a
   reply or a proposal; the wake tool policy denies the rest.
7. Durability: hot reload mid-poll causes no duplicate delivery; a killed
   session's lease frees after 3 minutes.
8. Failure paths: token swap gives one re-read then a band error; a closing
   keyword is refused by `crew-net state`; `doctor` flags a planted
   `allowManagedHooksOnly`.
9. Budget: one hour of polling stays within the request budget; 304s counted.

Two-login scenarios (sender identity, routing by the PR owner) wait for a
second account.

## Release checklist (W9)

- `plugin/.claude-plugin/marketplace.json` and README install line:
  `claude plugin marketplace add alexei-led/crew-net` then
  `claude plugin install crew-net@crew-net`.
- The plugin ships the built CLI; `crew-net doctor` passes on a clean config.
- README (front page), user guide (setup, daily use, settings, failure modes),
  repo-kit guide, CHANGELOG.
- `v0.1.0` tag on main with release notes.
